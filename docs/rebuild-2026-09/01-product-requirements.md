# Master 2.0 重构产品需求文档

版本：0.2 · 日期：2026-09-28 · 状态：AI + 语音优先需求基线；部分能力已在 Alpha 落地，完整验收仍未通过，见 [实际交付记录](./04-alpha-delivery.md)。本文中的目标与待验证数值不视为已达成。

“2.0”是本轮重构方案代号，不表示已有对应发布版本。语音中的“MAS”“端面”“光面”按上下文理解为 Master、桌面端、时间管理界面；暂不改产品名。

配套阅读：[调研与现状](./00-research.md)、[技术设计](./02-technical-design.md)、[AI 与语音智能体调研](./03-ai-agent-research.md)。

## 1. 产品结论

Master 是一个通过语音对话和工作记录，把想法、已做的事与现实时间连接起来的 AI 时间工作台。用户说说今天要做什么，或选取 Codex/其他聊天记录；智能体总结事实、提取目标，必要时主动问一个关键问题，再形成可以确认的计划与目标地图。用户聊完即可安排，随时能直接手改。

产品要减少“为了管理时间而维护工具”的负担。语音是核心入口，文字具有同等能力；表单与手工画图是可选的精细编辑方式。AI 负责理解与提出草案，确定性规则负责日期、容量、依赖和数据提交；用户保留最终决定。地图、清单和日历是同一批实体的不同视图。

产品吸引力来自自然、清新、富有空间感的视觉和连贯操作，持续价值来自“少维护、安排得下、完成后确实向目标推进”。主工作区保持今日行动与地图，助手按上下文出现，不把应用变成一张占满屏幕的聊天窗口。

### 已明确的要求

- Windows 电脑端优先，同时提供可在电脑浏览器使用的完整 Web 版。
- 首发必须支持真实语音采集、流式转写、智能体主动追问、结构化草案、语音/按钮确认和可撤销应用；文字输入与语音可在同一会话切换。
- 用户可主动选择 Codex/聊天记录，AI 提炼已做事实、未完成事项、目标与下一步；保留来源，区分事实、推测与建议，避免再次手工维护整份计划。
- 保留长期目标澄清、3–7 个关键要素、层级拆解、四象限、日/周计划及月/年规划复盘。
- 目标地图应包含可执行任务支链，并提供进度、投入、停滞、阻塞和截止风险反馈。
- 强调实用、清晰、自然审美、沉浸和流畅；后续可分享给他人使用并商业化。
- 先研究现有技术与开源项目，再形成需求和技术方案；重构需保留可迁移的原数据。
- 本轮优先级覆盖过去的移动端计划，iOS/Android 暂不进入新版首发范围。

## 2. 为什么需要重构

现有源码与历史桌面截图说明，当前版本已有业务原型，但未达到可靠的长期使用产品：

| 问题 | 用户影响 | 新版要求 |
| --- | --- | --- |
| 现有流程依赖向导、表单、逐项建图和手写复盘 | 维护计划本身消耗时间，记录与工具脱节 | 语音/文字/选定记录进入同一智能体，生成可审阅的增量草案 |
| “新建目标”会替换目标、任务与复盘集合 | 第二个目标可能覆盖原工作 | 多目标独立管理，新增与重置严格分离 |
| 各主要页面读取 `goals[0]` | 无法同时管理学习、健康、工作 | 多目标组合、目标切换、跨目标今日/周计划 |
| 画布是固定单向树，任务只在详情中 | 路径不直观，操作像查看图表 | 任务支链、局部展开、位置记忆和快捷操作 |
| 有子节点的父节点忽略直属任务进度 | 勾选后对应分支可能不变化 | 明确直属任务和子节点的统一聚合口径 |
| 新任务的计划日同时写入截止日 | “打算今天做”变成“今天必须做完” | 开始日、计划日、硬截止分离 |
| 各分支重复使用整个目标的周容量 | 看似都安排得下，整体却超载 | 用户级唯一时间预算，分支共享分配 |
| 月/年主要是展示，复盘缺历史事实快照 | 难以解释本期投入和变化 | 独立周期计划、时间记录与复盘快照 |
| 全量状态持久化、缺备份与失败反馈 | 数据量增长后存在延迟与可靠性风险 | 事务存储、明确保存状态、导入导出与恢复 |

具体证据见调研文档。以上是源码审计与历史截图观察；本轮尚未运行新版或取得 Windows 性能实测。

## 3. 首要用户与使用场景

主场景：一个人同时推进 2–5 个中长期目标，每天有碎片任务、固定安排和有限精力，希望看清投入是否服务于目标，又不想维护复杂项目管理系统。

四个核心任务：

1. “今天推进作品集，下午还要开会。”直接说话；智能体只追问影响安排的关键约束，聊完生成今日计划。
2. “这是我今天和 Codex 的记录，帮我看看做了什么，明天怎么接着做。”提取有来源的进展、待核实完成项和后续行动，不把助手的完成宣称当作已验证事实。
3. “任务越来越多，今天其实只能拿出两小时。”AI 根据现有目标和保护时间缩减承诺；用户能说“保留运动，把写作移到明天”或直接拖动修改。
4. “忙了一周，重要分支没有推进。”AI 先形成可核对的复盘与下一周草案，用户补充真实原因，无需重新填写一套总结表。

早期不把企业项目审批、研究资料管理、笔记百科和重型日历集成作为主要场景。

## 4. 信息架构与界面职责

主导航保持四项：今日、目标地图、计划、复盘。全局固定“说一说”入口并提供文字切换；收集箱、记录导入和搜索有固定位置。四象限是计划内的优先级视图，也可快捷打开。助手沿用当前目标、日期和选中内容，用户可以看到并调整本次使用的上下文。

| 界面 | 首要问题 | 默认展示 | 次级操作 |
| --- | --- | --- | --- |
| 今日 | 现在做什么？今天安排得下吗？ | 1–3 个可调整重点、行动队列、容量余量、说一说入口 | 专注、语音调整、查看来源路径 |
| 上下文助手 | 这次要理解和改变什么？ | 流式转写、一个关键问句、可编辑草案与差异 | 切换文字、停止收音、查看证据、按项排除 |
| 目标地图 | 为什么做？下一步在哪里？ | 已确认结构、下一个行动、少量真实风险 | 预览 AI 新支链、展开分支、大纲、编辑关系 |
| 计划 | 哪些任务值得做？何时做？ | 本周容量、候选任务和日程 | 四象限、月规划、年度方向、跨周导航 |
| 复盘 | 这段时间发生了什么？下一步如何调整？ | AI 草拟的本期事实、来源、关键变化和下一期建议 | 语音补充、修正事实、历史记录 |
| 收集箱 | 先把想法记下来 | 未整理事项 | 关联目标、定时长、归优先级、删除 |
| 设置与数据 | 数据在哪里？什么内容会发送？ | 本地保存、AI 文本/音频发送、导入范围与同步状态 | 账号/额度、备份、主题、播报、快捷键 |

地图与今日互相定位，保留选中对象、缩放、滚动与过滤状态。助手与详情共用上下文侧区，草案显示新增/改期/待核实/保持不变，不重排已确认地图。首次用户看到“说说今天想做什么”、文字输入、导入记录和示例；空白手建目标仍可使用。示例处于独立空间，不能混入真实数据。

### 桌面空间分配建议

- 1440px 宽度参考：左导航约 196px；主区域自适应；详情栏约 336px，默认收起。
- 地图首屏有清晰的中心目标与分支，避免所有对象都变成同尺寸的白色大卡片。
- 今日以工作内容为中心，缩小旧版大标题和统计卡的占屏；容量与目标来源就近展示。
- 小于 1180px 时详情栏改为覆盖面板；1024px 窗口仍能完成完整流程。125%/150% Windows 缩放须单独验证。
- 浏览器窄屏提供大纲/列表降级，但不以手机布局反向约束电脑端首发。

## 5. 完整用户 SOP

### 5.1 初次进入与数据准备

默认入口是“说说今天想做什么”，旁边提供文字、导入记录、体验示例和手工创建。首次用麦克风时说明收音与音频发送范围，用户点击后才开启；已有有效授权的同范围会话不反复弹确认。AI 服务是否需要账号或试用凭证由接入方案确定，不能因此阻止访问本地已有数据。

旧版结构化数据迁移与聊天记录导入是两条流程。旧版迁移保留原字节、ID、日期语义、异常清单和备份；旧累计工时缺发生日期时只列“旧版累计记录”，不伪造会话或计入严格本期投入。任何导入均不替换整个工作区，草稿可退出恢复。

### 5.2 说话、转写与切换文字

用户点击开启会话，界面显性显示“正在听”、输入音量、可见转写、停止和取消。首发需要应用自己的语音采集与流式识别通路，在 Windows 与支持的桌面浏览器实际验证；系统听写可应急输入文字，但不能作为“语音能力已交付”的证据。不默认常驻监听，不在用户结束会话后继续收音。

临时转写可以变化，只有稳定后的本轮文本参与意图确认；用户可修正“明天，不，后天”等口误。标题、日期、时长和否定词识别有疑义时就近标记，可直接改字，不要求整段重说。文字输入与语音共享上下文、证据和草案，用户随时切换。

智能体的关键问句可用简短语音播报，同时显示文字；播报可关闭或立即打断，首版用户点击/按键开始新一轮说话时停止播报。无需点击的自然插话另做全双工验证，不以此代替首版语音闭环。播报内容不能被再次识别成用户指令；失去设备、权限或连接时明确停止，保留已确认转写并可转文字继续。

### 5.3 智能体主动问关键问题

智能体先利用用户本轮输入和已授权上下文，区分已做事实、未完成意图、硬约束与候选建议。信息不足且确实影响安排时主动问，例如“今天这两小时里，需要给哪件事优先保留时间？”每轮最多问一个核心问题，常见场景通常 0–2 轮；不是把完整目标表单改成逐条口头盘问。

低风险未知采用可见假设先出草稿：没有估时可给标明“AI 估算”的建议时长；不明确的目标归属可先放收集箱。缺少真实截止、已完成证据或总容量时保留未知，不能伪造确定值。用户可以说“先这样”“先给个草案”跳过非关键问题；超过常见轮数时说明缺什么并保留现有草稿。

用户级容量先于各目标承诺；智能体能看到已有目标、固定安排和锁定项，新增目标不得再次分配同一份可用时间。用户可补充成功标准、限制与长期日期，但不是生成第一份今日计划的前置门槛。

### 5.4 生成可审阅的计划与地图草案

智能体提出今日/本周行动、建议时长、目标归属和可解释的优先级；需要时渐进提炼 3–7 个要素与成果节点，不为一句简单输入制造完整大图。系统校验日期、容量、依赖、重复项及实体关联。超额任务放入候选区，缺前置条件的行动不能伪装成可以立即开始。

草案展示新增、修改、待核实与保持不变，含来源/假设/理由。地图在独立草案层预览新支链，已有确认节点的位置、折叠状态与用户固定位置保持稳定。可用语音说“保留运动，把写作移到明天”，也可直接编辑字段或拖动；默认不改用户锁定或明确手改过的值。

### 5.5 一次确认、原子应用与手改

默认对当前草案进行一次批量确认，可按项排除，不逐字段弹窗。按钮或明确语音“按这版安排”绑定当前可见的草案 ID、版本和操作摘要；只有稳定识别且版本仍有效才提交。草案已更新、上下文不明或识别不确定时不猜测同意，返回清楚的当前版本。泛泛的“好的”不能授权删除、覆盖、上传新增范围等操作。

用户对已展示版本说“把第二项改成十五分钟，按这个安排”时，若指向唯一、转写明确、只有有限低风险修改且校验通过，可以在同一轮修改并应用，不再机械多问一次。授权绑定旧版、用户明确修改及最终差异；若模型新增了用户没说的内容、发生并发变化或有高影响操作，再给新预览确认。

确认后的有限变更集通过同一领域命令入口，在一次事务中应用；重复确认返回同一结果。后台较慢的旧草案不能覆盖新的手改，冲突项目留在差异预览。用户确认的仅是预览范围；“安排”不同时确认导入历史中的待核实完成状态，也不授权外部消息、发布或整库同步。

计划应用后仍能直接增删改、拖动与锁定，不需先和 AI 对话。成功显示本地保存回执；失败保留草案，不宣称已安排。批量撤销只补偿本次变更，保留随后独立的手工修改；冲突项可单独处理，不用整库旧快照覆盖。

### 5.6 从 Codex/聊天记录接续工作

用户粘贴、选择文件或选定来源范围后，系统解析作者、消息时间、引用和正文，先展示将处理的范围。自动导入属于单独开启的范围策略，不能因导入一段记录就扫描全部聊天或设备目录。识别到凭证等敏感片段时先在发送前处理并可审阅；聊天中的指令是来源文本，不是对应用的新授权。

AI 产出“已提及进展、待核实完成、待办与阻碍、建议下一步”。每项事实能回到消息/片段，区分用户自述、工具证据、助手宣称；导入历史中的完成事项默认待核实，不自动把对应任务勾完。修改代码不等于测试通过，测试通过不等于已发布。用户可一次确认选定的真实完成项；其余待核实项不会阻碍生成未来计划。

重复导入、部分重叠片段和追加新消息按来源身份去重，只生成增量建议；相似标题不能直接合并为同一任务。缺少发生日期的旧记录不强行归入今天，缺少耗时不生成实际时间。

### 5.7 执行、反馈与复盘

今日页面直接开始行动；专注保留当前任务、计时、暂停、完成和返回。计时可不用，完成不强迫填时长，未知投入保持“未记录”。语音说“这件已做完”时解析当前指向，歧义时才问；完成确认遵循同一可审阅命令与保存回执。勾选后直属节点与祖先执行进度同步，重复事件不重复记工时，休眠计时异常需确认。

每日结束可说一段进展，或导入本次工作记录。AI 草拟当天总结和遗留建议，用户可补一句原因、手动修正或直接暂存；不强迫把所有遗留任务推到明天。周/月/年复盘延伸同一流程，历史事实与下一期计划各有来源和状态。

### 5.8 授权、保留与离线边界

分别展示并控制 AI 文本发送、音频发送、来源自动导入与跨端同步；开启一项不自动开启其他项。会话开始前说明本次发送范围，既有同范围授权可复用，新增范围需显式选择。仅允许文本发送时，不将原始音频偷偷发给远端识别；若缺可用的本地识别通路，明确提供文字输入。

默认不长期保留原始录音；转写、证据摘录、来源文件引用和原文保留分别有可见策略与删除入口。自动源不存在或授权撤回时，不继续读取；已经采纳的任务可保留必要来源标记，原文被删后显示“来源已移除”，不能伪造可回溯证据。

断网仍能手工处理已保存任务、地图、计划与复盘；未具备离线语音/模型时明确显示相应服务不可用，保留已确认文本并允许稍后重试。不得把系统听写、演示转写或预录结果当作应用自身实时语音能力。

## 6. 拆解与图谱规则

### 6.1 对象与层级

| 对象 | 定义 | 最低信息 | 完成判断 |
| --- | --- | --- | --- |
| 目标 | 一项值得实现的最终变化 | 名称；草稿可暂缺日期/标准 | 成功标准验收，不单凭任务勾选 |
| 要素 | 目标成功所必需的关键方面 | 名称、所属目标 | 看子成果与相关行动，不靠花了多少时间 |
| 里程碑 | 可验证的阶段成果 | 交付结果、验收条件、可选日期 | 用户确认条件达成并可留证据 |
| 子目标 | 要素下可进一步拆解的中间结果 | 名称、父节点、可选验收条件 | 以成果验收为准 |
| 任务 | 可以开始执行的一次行动 | 动词与对象；归属和时长可后补 | 完成动作，可附实际投入与产出 |

推荐结构为“目标 → 要素 → 里程碑/子目标 → 任务”，允许跳过不需要的层级。要素建议 3–7 个，不做硬性系统上限；草稿可从 1 个开始，超过 7 个时提示合并。任务建议以 15–90 分钟可推进为粒度，超过 120 分钟建议拆分或多次执行，不强制拒绝。

AI 可从对话和选定记录提炼候选目标、成果与任务，但必须标明哪些来自用户、哪些为建议。只有采纳后才成为正式对象；不会为了补齐层级自动增加无意义节点。“学习”“努力”等模糊内容先作为收集项，AI 提出可执行改写，不因此反复盘问或阻止形成其他有效行动。

示例：完成求职作品集 → 项目案例 → 一篇案例达到发布标准 → 整理用户访谈洞察 45 分钟。45 分钟若来自 AI，须标为估算；只有用户明确的日期才能直接作为已确认硬截止，候选日期留在草案。

### 6.2 图谱关系

- 归属树 `contains`：除根节点外每个节点只有一个父节点，每项任务最多一个主归属节点；不允许循环。
- 前置依赖 `depends_on`：用于明确“完成 A 才能开始 B”，单独做无环校验；首个核心版本至少支持任务依赖。
- 一般关联 `related_to`：用于补充语义，不参与进度加权或时间重复统计；基础版本可先在详情展示。
- 跨目标关联可以引用同一任务，但只有主归属参与进度与投入汇总。
- 删除分支显示受影响节点与任务数量，可选择移入收集箱/迁移归属/归档；提供回收站。存在依赖时显示关系影响。
- 暂停目标后不继续发送推进提醒，但历史可见。归档与删除分开。

首版是“有类型关系的目标行动图”，需要提取目标/行动事实，但不要求扩张成百科式知识抽取系统或引入专用图数据库。

### 6.3 进度、成果、活跃度与风险分开表达

执行进度为完成的行动/子分支贡献占比；成功标准验收是独立状态。完成所有行动只提示“可验收”，不直接宣布目标成功。

执行进度采用可解释的加权聚合：父节点的贡献项包括直属子节点和直属任务；默认权重为 1，可调整。未完成任务贡献为 0，已完成为 1，取消/已删除对象不进入分母。没有行动的分支显示“无行动记录”，未验收时同时提示“待拆解”；父级计算时仍占权重且按 0 处理，不能因没有任务就消失或变成 100%。成果验收独立显示，例如“成功标准 2/3 已确认”，不改变行动完成比例。已验收但仍有未完成任务时，提示用户整理余留行动，不自动完成或删除。

新增/取消行动、变更权重会改变执行进度，提示“计划范围已调整”；成果验收只改变验收状态。AI 未采纳草案和待核实历史声明不参与执行率、实际投入或已验收数量。历史复盘保留当时快照，不随当前计划被静默重写。进度不按实际工时奖励，防止把忙碌误当成果。

活跃度依据近期有效时间记录、任务完成或验收；仅修改标题不算推进。默认 7 天观察窗，可按目标节奏调整；暂停与计划尚未开始的目标不标“停滞”。

风险分为“资料不足、正常、需关注、超期/容量不足”，另有独立阻塞标志。必须显示理由和对应数据，例如“截止前预计还需 180 分钟，已分配可用 120 分钟”。算法阈值是产品规则，不是对成功概率的预测。

## 7. 四象限、时间与容量规则

### 7.1 同一任务，多种视图

地图、今日、四象限、计划、专注、复盘引用同一任务 ID。改标题、完成、改期只执行一次业务命令；不在视图间复制任务。

重要性由用户决定，AI 可结合已确认目标提出理由与初值，经采纳后生效；紧急程度按硬截止与可配置窗口提示，可手动覆盖。没有评估过的任务显示“待判断”，不能直接当作不重要不紧急。用户覆盖值与锁定项在后续重规划时优先保留。

| 象限 | 默认建议 | 不应发生的行为 |
| --- | --- | --- |
| 重要且紧急 | 优先处理并检查容量 | 自动夺走所有健康/休息时间 |
| 重要不紧急 | 给长期目标预留稳定时段 | 被无限期挤出本周 |
| 不重要但紧急 | 精简、批处理，必要时记录委托 | 首版虚构已通知他人或多人协作 |
| 不重要不紧急 | 延后、取消或主动保留 | 系统直接替用户删除 |

### 7.2 日期语义

- 开始日期：在此之前通常不进入执行候选。
- 计划日期/时间段：用户打算何时投入，可反复调整，不等于截止。
- 硬截止：外部承诺或最后完成时间；可为空。日期型截止按用户时区当天结束处理。
- 同一任务可跨天安排多次投入，每次分配分钟数；完成状态属于任务本身。
- 移动计划不能把进行中/阻塞/取消状态意外改成待办。
- 对话中的相对日期按本轮时间与用户时区解释并显示具体日期；旧日志按原消息时间与时区解释，原时间未知就待确认，不能按导入当天推断。

### 7.3 唯一容量账本

先定义每天可支配时间窗口并取并集，扣除窗口内固定事件和保护时间，再预留默认 20% 的弹性缓冲（可调整）。重叠的事件按时间并集扣除，家庭/健康活动不能既作为固定安排又重复扣一次。AI 从对话提取的可用时间与保护安排在草案里可见，不要求用户先维护完整周模板。

也支持只说“今天还有一小时可用”，先建立净分钟预算，不要求再回答具体起止。草案明确按“已扣固定安排、尚未预留弹性的一小时”理解，经采纳后只再扣缓冲，不重复扣会议；有歧义时就近询问。净分钟与时间窗是同一天的两种容量模式，不相加；改为时间窗时预览替换差异。没有起止时可以形成今日队列，不能宣称具体时间段无冲突。

`可计划容量 = max(0, 窗口总分钟 - 不可用时间并集分钟) × (1 - 缓冲比例)`。

全部目标共享此容量。日任务分配与时间块表达同一份计划：时间块占用已分配分钟，不叠加计算。全局容量超载先报警，再展示各目标的占比。无估时任务单独标“容量尚未覆盖”，避免显示虚假的充裕。

示例：可支配 180 分钟，固定安排 30 分钟，缓冲 20%，可计划 120 分钟；已安排两个任务各 60 分钟后，新增 45 分钟任务应显示超额 45 分钟。

分钟总量与具体时间段冲突分开判断。即使一天还有余量，两个任务都排在 10:00–11:00 也应提示重叠，个人时间块不默认可并行。

执行中同时显示“已投入”和“剩余承诺”，不把实际与同一份计划重复相加。已完成任务用掉的时间仍属于当天消耗；无时间记录则显示不确定，不因勾选就把它全部变回空闲。提前完成或取消时保留已发生的计划/投入历史，预览并释放未来尚未执行的分配，可撤销。剩余工作量需要估计或重新确认，不将总估时减累计实际机械当成可信的剩余工作。

## 8. 动态反馈

| 事件 | 数据变化 | 可见反馈 | 异常/回退 |
| --- | --- | --- | --- |
| 开启/停止会话 | 会话状态、有效授权与转写草稿 | 正在听/识别中/已停止；文字可修正 | 拒绝权限或断线后保留文本、停止收音 |
| AI 追问或生成草案 | 问句、来源与带版本的建议变更集 | 一个关键问题、增量差异与独立地图预览 | 可中断、切文字；过期结果不覆盖新状态 |
| 确认草案 | 一批有限领域命令与提交回执 | 已安排摘要、仍待核实的项目和撤销 | 原子提交、幂等重试、手改冲突可见 |
| 完成任务 | 完成事件、任务状态、可选时间记录 | 勾选即时反馈；相关路径短暂强调 | 重复命令幂等；可撤销 |
| 新增行动 | 新任务、归属、贡献分母 | 新支链展开在附近；显示范围变更 | 保存失败保留草稿 |
| 分支有投入未完成 | 时间记录、活跃度 | 投入标签更新，不伪造完成率 | 无记录不推断无工作 |
| 截止临近/容量不足 | 派生风险重算 | 文字理由和克制的风险标记 | 缺时长显示无法判断 |
| 改期 | 日分配/时间块更新 | 余量即刻变化，来源目标保持 | 冲突时间段可调整 |
| 暂停/恢复 | 目标状态与节奏基线 | 分支视觉降低强调/恢复 | 历史投入和成果不丢失 |

自然效果与语义绑定：分支亮度/描边表达当前选择与最近推进，进度环或数字表达执行比例，风险有文字及图标。不用“树枯萎”惩罚休息，不让完成动画阻塞下一次操作。

## 9. 周、月、年规划与复盘

### 9.1 周度

展示本周计划与实际记录、关键成果、延期/取消、各分支投入、未记录时长数量、保护时间保留情况。既看投入，也看成果，不把完成任务数当唯一价值。

流程：AI 草拟本期事实和来源 → 用户语音/文字补充或纠正 → 必要时问一个关键阻碍 → 生成下周重点和容量草案 → 一次确认应用。未完成项可重新估时、拆分、推迟或取消；用户决定是否延续，不需逐项重写旧计划。

### 9.2 月度

AI 比较本月与上月的可用事实：成果验收、投入分布、过载频率、重要不紧急任务投入，并标明记录缺口。围绕目标是否仍值得做、要素是否遗漏、现实限制是否改变进行简短对话。输出下月重点成果、要素预算和应停止事项的草案，不生成一整月无法维护的细碎任务。

### 9.3 年度

AI 总结各生活领域的已确认成果与投入；满意度和个人意义通过用户表达补充，不能由模型替用户断言。归档完成/放弃的目标需确认。下一年先通过对话确定少量方向与季度里程碑，再逐步细化，主动保留假期、恢复期和家庭安排。

### 9.4 分析建议的可信边界

- 周/月/年使用对应周期的时间记录和事件；明确区分“本期投入”与“累计进度”。
- 已完成复盘保存数据截止时间、时区、计算规则版本与快照。补记历史时间时提示重算并生成修订版。
- 建议必须附理由与可执行动作：例如“学习分支本周记录 0 分钟；可从下周三未占用容量安排 30 分钟复习”。记录不足时说“未记录”，不说“你没有努力”。
- 进入执行计划的任务应未完成、满足前置条件、日期允许且容量可容纳。没有合适候选时，AI 可提出有理由的新行动草案；不能把新建议写成过去已做的事实。
- AI 是首发的理解、追问、提取和计划入口；容量、日期、依赖与持久化仍由确定性规则校验。模型输出不直接完成任务、改变验收或覆盖已确认计划。
- 事实、推测、估算、建议分别标注。历史助手宣称、用户自述和工具证据保留不同来源身份；既有证据不支持时显示“待核实”，用户可以一次核实多项而不被反复确认打断。
- 复盘文字的每个关键事实可追溯；来源移除或数据不足时降低结论强度，不编造时长、情绪、成果或因果。AI 不可用时仍可阅读、编辑本地复盘。

## 10. UI/UX 设计规格

### 10.1 视觉方向：自然空间中的清晰行动

这是面向长期个人使用的桌面产品。采用接近雾白的浅底、矿物绿主色、深墨文字，局部静态材质、枝状关系和自然的疏密变化形成空间感。分支位置稳定，用户可以形成空间记忆。

| 令牌 | 浅色提案 | 深色提案 | 用途 |
| --- | --- | --- | --- |
| canvas | `#F4F7F4` | `#111A16` | 画布底色 |
| surface | `#FBFCFA` | `#19251F` | 任务与详情阅读区 |
| text | `#20352B` | `#E6EFE8` | 正文 |
| text-secondary | `#56685D` | `#ADBCB1` | 辅助信息，仍需实测对比度 |
| accent | `#2F6B52` | `#93C5A6` | 主要动作/选中 |
| line | `#DCE5DD` | `#34483C` | 内容组织，不能代替焦点标记 |

颜色为设计提案，实际组件需验证对比度。风险可用低饱和琥珀/红，分支身份可以用辅色，但主动作统一。

- 正文 14–16px，任务行以 15px 为起点，主要标题 26–32px；字体自托管或系统回退，中文阅读优先。
- 间距基于 4/8px，常用 8/12/16/24/32；按钮约 36px 高，图标按钮建议至少 32px 点击区域。
- 节点形态分层：中心目标较大、要素为轻量分组、里程碑为结果卡、任务为可操作短行。
- “参差感”来自内容长度、分组与留白；菜单、详情、快捷操作位置一致。
- 保留植物/自然意象用于欢迎、空状态和复盘封面。工作区不铺满照片，不持续播放背景视频。
- 首发至少提供浅色、深色、跟随系统和减少动效；不承诺首发主题商城。

### 10.2 地图具体交互

首屏展开目标与要素，分支默认显示下一行动摘要。选择分支后局部展开里程碑和任务；密集关系只在选中上下文显示。远景看结构，中景看成果，近景编辑任务；提供固定缩放按钮和“回到目标”。

鼠标拖动空白平移，滚轮行为可设置，提供明确缩放修饰键。拖动节点仅改变展示位置，拖动任务到计划日仅改变排期。任何拖拽都提供菜单替代。

键盘可通过命令面板搜索、创建与导航，通过大纲完成节点增删改、任务完成和排期。编辑中文输入法组合期间不能误触发 Enter 创建/完成命令。

### 10.3 动效与无障碍

选中反馈约 100–140ms；详情展开约 160–220ms；地图定位约 220–300ms，手动操作立即打断。完成反馈只作用于相关节点，避免全图重排。

所有非必要动画可关闭；降低动态效果时保留状态变化和文字反馈。普通正文对比度至少 4.5:1，大字至少 3:1，关键非文本控件至少 3:1；颜色不是唯一状态渠道。参考 [WCAG 2.2](https://www.w3.org/TR/WCAG22/)；本项目额外采纳可关闭交互动效的要求。

### 10.4 语音会话与草案界面

今日主区域保持行动队列；底部或上下文侧区容纳短会话，不用大段机器人文字替代真实任务界面。会话状态至少区分未收音、正在听、识别中、待用户回答、生成草案、待确认、应用中、已保存、失败/已取消。麦克风状态不能只依赖颜色，停止收音有始终可达的按钮和键盘入口。

问句只展示当前最重要的一项，可同时用短音频播报，默认不朗读整张计划。草案紧邻今日安排或地图，突出“新增 3 项、改期 1 项、保留锁定 2 项”，能展开来源与详细差异；待核实历史完成单列，不混在未来安排的确认里。

用户边说边看到稳定文本，临时转写不让正式任务跳动；只有明确确认后更新工作区。AI 草案层与正式地图有文字标签区分，应用时只调整确有结构变化的局部，已确认地图不得每轮对话全图重排。文字、按钮和大纲具有与语音等价的核心操作能力。

## 11. 性能与可靠性验收目标

以下是待实现的项目目标，不是既有测量结果。测试机与测量方法见技术文档，至少覆盖 Windows 集成显卡与 Edge/Chrome。

| 场景 | 目标 |
| --- | --- |
| 勾选、选中、键盘输入反馈 | 受控测试 p95 ≤100ms |
| 点击收音/停止、取消与打断反馈 | 本地可见状态 p95 ≤100ms；结束后停止设备采集，不能只隐藏指示 |
| 流式语音识别 | 初始预算：首段可识别语音送出至首段转写 p95 ≤2s；停说至稳定转写 p95 ≤2s，记录端点判定、网络、设备与识别服务 |
| 智能体关键问句/计划草案 | 初始预算：稳定输入提交至短文字问句 p95 ≤3s、问句首段可听响应 p95 ≤4s、短场景完整可操作草案 p95 ≤10s；≤1分钟转写/≤2000中文字符，流式首字不算草案完成，大文件另列进度 |
| 已加载页面间切换 | p95 ≤150ms |
| 地图拖拽/缩放 | 60Hz 基准连续操作，帧间隔 p95 ≤20ms，>50ms 长帧占比 <1% |
| 本地保存 | 单次普通命令持久提交 p95 ≤200ms，失败可见，不丢失已确认保存的数据 |
| Windows 启动至可交互 | 发布构建目标 p95 ≤2s，实际值以原型测量调整并记录 |
| Web 线上使用 | INP p75 ≤200ms；Web 初次加载单列网络条件，不与桌面冷启动混算 |
| 数据规模 | 标准场景 1,000 任务/150 可见节点；压力场景 10,000 任务，渐进展示 |
| 离线使用 | 已准备资源后，手工创建、完成、搜索、复盘与重启仍有效；无离线模型/识别时明确 AI/语音不可用，不伪装在线成功 |
| 数据可信 | 迁移、撤销、保存失败、升级和同步冲突均有可验证恢复路径 |

INP 的定义与良好阈值参考 [web.dev](https://web.dev/articles/inp)。缩放/拖拽流畅性另外测量，不用 INP 代替帧数据。

语音与模型预算需在 M0 对选定服务、固定中文语料、网络条件和音频长度实测后锁定，以上不是已经达标的结果。问句/生成可以异步进行，等待期间手改、查看和停止都可用；长输入不为追求显示速度而跳过证据和事务校验。另统计日期/否定词转写错误、误确认、事实提取错误、人工纠正次数与单次调用成本。

## 13. 商业化编排

暂推荐“本地基础能力 + 限额 AI/语音试用 + Pro”的路线。首要付费价值是理解工作记录、通过短对话形成可执行计划与持续复盘带来的省时，之后才是跨设备同步、历史恢复和模板。基础数据访问、手工修改、备份导出不作为付费封锁点；停止订阅或 AI 用量耗尽仍可使用和导出自己的内容。

AI 额度、实际录音/识别分钟、语音播报与模型推理费用分项核算，按实际供应商计量口径展示清楚的套餐范围。M0/M1 记录每个成功计划、每份导入和每次复盘的成本，含失败/重试放大；录音分钟不能简单冒充完整 AI 成本。默认不自动追加收费，额度不足时保留草稿、说明原因并提供手工继续。价格需结合省时价值、接受率和单位服务成本验证，不预先承诺无限量。

分享有三层：软件安装包/网址分发；只读目标模板或复盘图片导出；后续可撤销的只读链接。首发不默认公开个人任务。在线分享上线时需明确范围、到期/撤回，以及用户主动选择后才能发布。

付费到期后本地核心数据可继续访问与导出，在线 AI、音频服务和同步权益分别按明确规则处理。账号注销、远端记录删除、本地保留与来源授权撤回分别说明；不能把退出账号当成音频已被供应商删除的证明。同步服务必须可看状态与恢复失败，登录成功不等于已经备份。

中国大陆/全球市场确定后，再明确部署、账号验证、支付、隐私文本和分发渠道。现在只定义接口与上线检查项，不写未经核验的具体法律结论，也不采购外部服务。

## 15. 试用验证与待对齐项

邀请 5–8 名符合目标用户的试用者，用相同合成材料分别走手工与智能体流程，并交错体验顺序以减少熟练度影响。至少覆盖三组：说出今天的想法并回答关键问题；导入含未完成/矛盾/敏感占位符的 Codex 风格记录；手改后重新规划并完成一次周复盘。用户自愿提供真实记录时另行明确范围，测试默认不读取私人聊天。

“维护耗时”包含表达需求、回答追问、审阅、纠错、手动改期和最终确认；另外报告系统等待时间，不把等待剔除后宣称端到端更快。记录首次可用计划时间、手工字段数、澄清轮数、事实修正次数、误完成/误确认、计划采纳率、锁定项保持、次周是否继续使用和采纳后真实执行情况。严重误完成、越权发送、破坏手改和不可恢复数据损失在固定测试集中必须为零；不据小样本宣称现实零风险。

初始价值假设是智能体流程较手工基线减少至少 30% 的维护耗时，同时不增加事实错误和排程约束违反；这是待验证门槛，不是既有结果。M0 后根据真实基线记录是否调整，不能只统计成功样本、删掉重试或把系统听写当完整语音组。小样本用于发现问题，不代表市场统计结论。

激活定义为用户通过真实语音或等价文字/记录输入形成草案，确认应用后开始一次关联行动；地图/四象限一致、本地保存成功是必要条件。不要以聊天轮数、停留时长或动画观看时间作为成功指标。遥测默认只包含获得授权的最少汇总数据，任务正文、录音和来源原文不进入产品统计。

语音核心、AI 主动追问、聊完安排和随时手改已经明确，不再作为“以后是否做 AI”的待定项。上层市场/团队范围、具体模型与语音供应商、录音保留策略和价格仍需结合调研与试验确定；这些选择不阻止先验证已确定的 AI + 语音闭环。本文所有性能、质量与省时数值均为拟定验收目标，尚未实现或达成。
